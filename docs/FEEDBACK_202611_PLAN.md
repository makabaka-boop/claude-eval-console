# 2026 年 11 月领域专项改造计划

目标是在现有 Python HTTP、SQLite 和静态页面架构上，完成“建题 → 单会话任务与中断续写 → 保存证据 → 指定模型分析与复核 → 导出”的专项流程。实施范围分六批，首版将关联的前后端一并接入，以完整可用流程进行验收。

当前分支为 `codex/feedback-202611-domain`。本计划基于 `3405c3f` 的恢复版代码制定；以下保留原设计与验收标准。2026-11-11 已实现第一至五批的专项代码及本地测试闭环，默认首页已切换到新流程；真实任务验收和第六批正式对接尚未完成。恢复版的已知完整性限制见根目录 `RECOVERY_STATUS.json`。

## 2026-11-11 实施与验收记录

- 新模块位于 `feedback/`，不复用旧 A/B 归档、评分、自动演示生成和提交链；只复用已有容器启动、screen 发送、原始轨迹复制与并发基础设施。默认启用专项模式，历史入口改为只读查询与证据下载，旧写入接口全部拒绝。专项迁移前保留独立 SQLite 备份。
- 领域初始未选择，实际建题前再固定；采用专项枚举、不可变题面附件和单执行记录。相同仓库可多题，每次独立重跑有单独现场；重复开始幂等。中断继续登记发送状态，首轮 ID 不被覆盖，发送结果不明时不能直接重发；续写也受单并发限制，重启先计入已有执行再启动排队任务。
- JSONL 校验原始题面、Session、首轮和续写 PromptID、额外业务输入及完成边界，归档保留完整原文与哈希。正常 Git 提交追加在模型 HEAD 上，保留中间提交并验证初始快照的祖先关系；推送到各执行独立分支，无强推或压平。
- 提供最终 SHA 的干净录屏工作区和人工视频导入，读取实际时长，不对超长视频截值；失败产物允许录屏。自动录制器和演示路线生成未迁入首版，避免继续调用旧分析模型。人工需实际运行、录制和播放确认，文件存在或时长可读不代表功能运行成功。
- 指定 `gpt-6.1-sol` high 的独立只读分析任务读取完整 JSONL、初始/最终代码和原始附件，保存请求审计与原始结果，核对结果和过程的文件引用；不运行猜测的验收命令，不编造测试数量。证据变化后旧分析/确认失效，分析失败只重试分析，不重跑甲方任务。提供方未单独回传模型标识时审计记为未知，真实服务映射仍待实测。
- 已新增独立导出列表入口：分页展示全部已归档执行（含待补齐记录），支持关键词、任务类型和资料状态筛选，保留跨页勾选，批量核验并导出 Excel/JSON；每行可进入对应执行详情补齐资料，导出时重新进行完整证据核验。
- 支持结果/过程 Feedback 草稿、1–5 分完整性、其他问题、备注、证据外部链接和人工确认；本地 Excel/JSON 采用专项 21 列，保留原始首轮定位。Excel 以文本写入，不截断长内容；超过单元格上限可改用保留原文的 JSON。缺少正式模板时前后端均阻止正式提交。
- 隔离测试使用真实 SQLite、Git 提交与本地 bare remote、完整 JSONL 以及模拟模型响应/合成媒体元数据，覆盖两次中断后归档、复核和一行导出。另检查复用的轨迹解析及终端启动基础设施；浏览器核对正式首页、领域待选、隔离建题及评价草稿。

## 第一批 P0 建立专项边界和恢复基线

先避免新任务进入旧流程，再开展新功能。

- 明确区分专项模式和历史 GSB 模式，后端返回当前模式及协议版本，前端据此展示入口。
- 专项入口不允许启动旧 A/B、改变甲方执行模型方案、调用未指定的分析模型或提交到旧 GSB 地址；后端直接调用也执行相同限制。
- 独立冻结分析模型和推理等级，校验 `gpt-6.1-sol` 与 high 的实际服务映射，记录请求和返回模型标识。配置错误时报告错误，不降级为其他模型或 medium。
- 历史记录保留可读，迁移前备份数据库。旧记录不会因新增标签被自动转换为专项样本。
- 记录恢复版现存的启动、导入、数据库、归档和录屏问题；先修复影响专项流程的依赖，不把修复所有历史功能列为本批前置条件。

验收：专项页面和 API 明确报告模式；旧数据可读；专项请求无法触发旧派发和提交路径；错误分析模型或非 high 配置被拦截；甲方模型和 Key 不被分析配置覆盖；数据库迁移可重复运行。

## 第二批 P0 新增专项任务与表单

- 增加个人本期固定领域、任务联动子方向、11 类任务标签、困难/地狱、原始 Prompt 和条件附件。个人领域可在实际出题前最后配置，当前不预选。
- 环境可复现等级按规范设为选填；保存实际 Harness、版本和操作系统。
- 使用统一字段定义维护前后端选项、预检和导出映射。
- 专项题目和执行记录独立于 Pair 的 A/B 关系；复用通用 `runs` 的执行字段，新增专项关联、续写和分析记录。支持同一 Repo 多题，不能沿用旧版仓库名唯一或仅 main/A/B 三个分支的约束。具体表结构在本批设计中确定。
- 每次独立 Session 绑定独立执行记录；重试关联原任务，不能覆盖旧 Session、轨迹或反馈。
- 分开保存首轮提交定位和各次续写的实际 TurnID/PromptID；增加“其他问题”字段及中断次数、时间和原因记录，续写不新增提交样本。

验收：通用模块可在个人领域未选择时开发和配置；实际出题前必须选择本期领域；跨个人领域建题被拒绝；同 Repo 可创建多道独立题；非法子方向及中等/简单难度被拒绝；首轮和续写定位不会相互覆盖。

## 第三批 P0 实现单会话任务与中断继续

- 点击一次开始只创建一条执行、一个工作区和一个 Session，锁定 auto 与 1M 配置。
- 发送 Prompt 前持久化状态，双击、并发请求或重启均不能重复发送。
- 提取并绑定实际 SessionID、TurnID/PromptID，保留原始轨迹和完成边界。
- 模型正常完成后结束任务，不追加新需求或纠错消息。模型自行中断时提供“继续本任务”，仍使用原 Session，保存每次输入和实际续写定位。
- “继续”不能当成新的业务 Prompt，也不能因此增加提交数据条数；重复点击和重启恢复要防止同一次续写重复发送。
- 全部续写结束后，最终产物和录屏绑定最新交付结果；分析覆盖完整执行，提交仍使用原始 Prompt 和首轮定位，在“其他问题”说明中断情况。
- 工程故障与自行中断分别记录。确需独立重跑时建立新 Session，完整保留失败现场，不把两个 Session 的轨迹合并。

验收：正常任务只产生一条执行；自行中断后连续两次“继续”仍只形成一条提交样本，首轮 ID 不变且续写 ID 完整保留；追加新需求不被当作继续；并行上限为 1 时可运行；重复开始、重复继续与重启恢复不重复发送。

## 第四批 P0 完成快照与录屏证据

- 归档前保存原始模型 HEAD 及提交链。模型有未提交产物时，按正常提交追加在当前 HEAD 上，不重建以初始快照为直接父节点的替代历史。
- 保存最终 40 位 SHA，通过 `git merge-base --is-ancestor` 核验初始快照，不 squash、不改写已提交历史。
- 复用现有轨迹复制、哈希、媒体读取和录屏基础设施时，为专项记录增加适配，解除 A/B 成对就绪条件。
- 支持人工运行与录屏文件导入/关联，并复用本地录制器。若生成演示路线需要分析产物，则使用指定分析配置并保留依据；完整录屏不能被演示脚本或分析文字替代。录屏绑定全部续写后的最终产物 SHA，核验文件存在、格式和时长。
- 模型产生构建错误或无法运行的产物，仍允许保存失败现场视频，交由专家评价；不因为结果差就自动判样本无效。

验收：含多个模型提交的仓库保留完整提交链；最终 SHA 对应归档的产物代码树；初始快照非祖先时阻止错误归档；成功和失败产物均能关联不超过 90 秒的真实运行视频，不剪掉失败过程；录屏失败不会被标记为成功。

## 第五批 P1 指定模型分析与专项导出

- 详情页集中展示原始 Prompt、首轮及续写 ID、快照、完整轨迹、录屏和“其他问题”。
- 使用 `gpt-6.1-sol` high 分析完整执行并撰写评价描述，Feedback 必须同时涵盖最终结果和执行过程；交付完整性为 1–5 分整数，最终结果经复核确认。
- 保存实际分析模型、推理等级、证据哈希及原始分析输出，区分分析草稿和最终确认稿；证据或续写变化后使旧分析失效，重新覆盖全部内容分析。
- 分析失败可重试分析阶段，不重跑甲方执行任务，也不静默替换模型或推理等级。专项提交不要求 GSB 结论、A/B 描述或五维评分。
- 评价中的测试结果优先引用与题目相关的文件和场景；数字必须对应真实输出，不强制生成测试数量，不隐瞒与需求相关的失败，不用仓库测试总量替代需求验收。
- 预检检查字段、证据、文件、首轮 ID、续写归并及指定分析配置；不直接沿用旧 GSB 的禁词和句式规则。
- 新增通用专项导出，正确保留长文本、换行和附件引用，禁止静默截断。正式模板确认后绑定其列名及枚举。
- 区分“模型结果差”和“工程故障导致没有反馈价值”，由专家结合证据决定样本有效性；低分不是拒绝导出的原因。

验收：一条样本完成指定模型 high 分析、复核和导出；中断前后内容都进入分析，导出仍引用首轮 ID；Feedback 同时含过程和结果，“其他问题”包含中断说明；1 分失败产物可导出；缺失证据、错误分析配置或过期分析被指出；专项载荷不含旧 A/B/GSB 字段。

至此形成第一版可用闭环。以当前已验证的执行环境为首批验收范围，不把支持新平台或全部专项运行环境作为这一闭环的前置条件。

## 第六批 P2 对接正式提交与日常使用

正式模板、提交入口、上传方式和鉴权范围确认后再实施。

- 对接完整轨迹、最终产物视频、初始/最终快照及专项字段，确保上传后有可直接下载或播放的证据链接；首轮定位与“其他问题”按正式模板映射。
- 为每次提交保存执行记录、载荷摘要和远端回执，避免断网重试造成重复提交；结果不确定时先核查远端状态。
- 增加领域、子方向、任务类型和提交状态筛选，以及日交付数量和截止时间提示。
- 根据专项真实使用情况，再安排批量调度和其他已获确认的执行环境。

验收：一条样本从本地归档到远端回执可完整追溯；重试不重复提交；上传失败保留本地文件；没有正式模板配置时不能误投旧 GSB 表单。

## 第一版延后的事项

- 重建旧版自动补题、长期题型配额和复杂候选库调度。
- 跨 Windows、Unity、GPU、固件等环境新增整套执行器。
- 全站视觉重设计和修复全部历史 GSB 功能。
- 新增向原 Session 追加需求或纠错的多轮工作流；允许的中断“继续”在第三批实现。

领域标签不能代替执行环境能力验证。安全、音视频、图形或数据任务需要特定环境时，先提供真实环境与证据采集方式，不一律套用原来的 Web/Docker 模板。

## 整体验收清单

1. 正常交付、模型代码报错、工程故障、中断和录屏失败分别有明确且可恢复的状态。
2. 不重复发送原始业务 Prompt；自行中断只允许已记录的“继续”，同 Session 的全部续写只提交一条样本，独立重跑另有新 Session。
3. 原始 Prompt、附件、全部续写轨迹及最终快照和录屏绑定同一任务；导出首轮定位，“其他问题”记录中断。
4. 多提交历史、数据库迁移、并发开始、重启恢复和上传重试均有针对性测试。
5. Feedback 使用指定模型和 high 配置，覆盖结果与过程，包含有依据的相关测试结果，并可复核后导出完整字段。
6. 专项分析不使用 DeepSeek、旧模型或 medium 默认值；甲方模型与 Key 保持执行用途，不会提交到旧 GSB 表单。
7. 至少跑通一条实际专项任务的完整闭环，由专家实际核对证据和反馈后再开放批量使用。
