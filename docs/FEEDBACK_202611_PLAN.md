# 2026 年 11 月领域专项改造计划

目标是在现有 Python HTTP、SQLite 和静态页面架构上，完成“建题 → 单会话首轮执行 → 保存证据 → 人工评分和 Feedback → 导出”的专项流程。计划分六批实施，每批独立提交并验收。

当前分支为 `codex/feedback-202611-domain`。本计划基于 `3405c3f` 的恢复版代码；标题已更新，执行、归档和导出仍按旧 A/B 规则运行。恢复版的已知完整性限制见根目录 `RECOVERY_STATUS.json`，实施前需重新建立相关测试基线。

需求来源：[在线规范](https://docs.qq.com/pdf/DVW1wYWFWd0VhekRO)、[仓库归档 PDF](specs/CC_Codex_feedback_26.11_domain.pdf) 和[需求对照](FEEDBACK_202611.md)。2026 年 11 月 11 日核对的在线关键页包括单轮字段、领域要求和任务类型附录；完整口径以归档 PDF 为规划依据，未将在线文件与归档文件作逐字节一致性认定。

## 必须满足的规则

| 事项 | 新专项规则 |
| --- | --- |
| 样本单位 | 一个 Session 的一轮有效交互组成一条样本，记录准确的 SessionID 和 TurnID/PromptID |
| 执行配置 | auto 模型，1,000,000 上下文；只跑首轮，不追问、不纠错 |
| 分类 | 三大领域及对应子方向，使用附录 11 类任务标签，难度仅困难和地狱 |
| 人工评价 | 交付完整性为 1–5 分整数，Feedback 为人工填写的过程与产物反馈 |
| 产物快照 | 使用最终 40 位 SHA，保留模型中间提交，以祖先关系核验初始快照 |
| 运行证据 | 原始 JSONL、快照、真实运行录屏；失败产物也录制，视频不超过 90 秒 |
| 提交 | 使用确认后的专项模板，不能沿用旧 GSB 字段和目的地址作为默认映射 |

规范禁止 AI 分析轨迹、产物或代写 Feedback。专项模式下，读取样本产物或轨迹的模型评审、反馈生成、难度复评及演示路线生成均需逐项隔离；元数据提取、哈希核验、Git 祖先关系检查和文件上传采用确定性程序完成。录屏先采用专家实际操作和确认的方案。

## 第一批 P0 建立专项边界和恢复基线

先避免新任务进入旧流程，再开展新功能。

- 明确区分专项模式和历史 GSB 模式，后端返回当前模式及协议版本，前端据此展示入口。
- 专项入口不允许启动旧 A/B、选择异模型、触发样本 AI 评审或提交到旧 GSB 地址；后端直接调用也执行相同限制。
- 历史记录保留可读，迁移前备份数据库。旧记录不会因新增标签被自动转换为专项样本。
- 记录恢复版现存的启动、导入、数据库、归档和录屏问题；先修复影响专项流程的依赖，不把修复所有历史功能列为本批前置条件。

验收：专项页面和 API 明确报告模式；旧数据可读；专项请求无法触发旧派发、评审和提交路径；数据库迁移可重复运行。

## 第二批 P0 新增专项任务与表单

- 增加所属领域、联动子方向、11 类任务标签、困难/地狱、原始 Prompt 和条件附件。
- 环境可复现等级按规范设为选填；保存实际 Harness、版本和操作系统。
- 使用统一字段定义维护前后端选项、预检和导出映射。
- 专项题目和执行记录独立于 Pair 的 A/B 关系；复用通用 `runs` 的执行字段，新增专项关联与评价记录。具体表结构在本批设计中确定。
- 每次独立 Session 绑定独立执行记录；重试关联原任务，不能覆盖旧 Session、轨迹或反馈。

验收：三领域和任务标签可保存、刷新后可恢复；非法领域与子方向组合及中等/简单难度被拒绝；Prompt 的空白、换行和附件对应关系保持完整。

## 第三批 P0 实现单轮执行

- 点击一次开始只创建一条执行、一个工作区和一个 Session，锁定 auto 与 1M 配置。
- 发送 Prompt 前持久化状态，双击、并发请求或重启均不能重复发送。
- 提取并绑定实际 SessionID、TurnID/PromptID，保留原始轨迹和完成边界。
- 最终回复后结束本轮，不自动追加修复题面、纠错消息或“继续”。“继续”例外等待项目方确认。
- 工程故障保留现场和原因。显式重跑时建立新的独立 Session；成功样本不沿用失败 Session 的 ID 或轨迹。

验收：正常任务只产生一条执行和一条有效 Prompt；并行上限为 1 时可运行；重复开始与重启恢复不重复发送；中断和工程故障的原始证据可追溯。

## 第四批 P0 完成快照与录屏证据

- 归档前保存原始模型 HEAD 及提交链。模型有未提交产物时，按正常提交追加在当前 HEAD 上，不重建以初始快照为直接父节点的替代历史。
- 保存最终 40 位 SHA，通过 `git merge-base --is-ancestor` 核验初始快照，不 squash、不改写已提交历史。
- 复用现有轨迹复制、哈希、媒体读取和录屏基础设施时，为专项记录增加适配，解除 A/B 成对就绪条件。
- 先支持人工运行与录屏文件导入/关联；复用本地录制器时不调用样本 AI 分析路径。录屏绑定实际产物 SHA，核验文件存在、格式和时长。
- 模型产生构建错误或无法运行的产物，仍允许保存失败现场视频，交由专家评价；不因为结果差就自动判样本无效。

验收：含多个模型提交的仓库保留完整提交链；最终 SHA 与工作区一致；初始快照非祖先时阻止错误归档；成功和失败产物均能关联不超过 90 秒的实际运行视频；录屏失败不会被标记为成功。

## 第五批 P1 人工评价与专项导出

- 详情页集中展示原始 Prompt、Session/Turn ID、快照、轨迹和录屏。
- 人工保存交付完整性整数分数、Feedback 和备注；保留草稿，证据变化后要求重新确认。
- 专项提交不要求 GSB 结论、A/B 描述、五维评分或模型复评结果。
- 预检检查字段、证据、文件和 ID 一致性，不使用模型评判或重写人工 Feedback，不直接沿用旧 GSB 的禁词和句式规则。
- 新增通用专项导出，正确保留长文本、换行和附件引用，禁止静默截断。正式模板确认后绑定其列名及枚举。
- 区分“模型结果差”和“工程故障导致没有反馈价值”，由专家结合证据决定样本有效性；低分不是拒绝导出的原因。

验收：一个完整样本可以人工评分并导出；1 分的失败产物样本同样可导出；缺少必要 ID、快照或录屏时清楚指出缺项；人工 Feedback 保存和导出内容一致；专项载荷不含旧 A/B/GSB 字段。

至此形成第一版可用闭环。以当前已验证的执行环境为首批验收范围，不把支持新平台或全部专项运行环境作为这一闭环的前置条件。

## 第六批 P2 对接正式提交与日常使用

正式模板、提交入口、上传方式和鉴权范围确认后再实施。

- 对接一组轨迹、一段视频、初始/最终快照及专项字段，确保上传后有可直接下载或播放的证据链接。
- 为每次提交保存执行记录、载荷摘要和远端回执，避免断网重试造成重复提交；结果不确定时先核查远端状态。
- 增加领域、子方向、任务类型和提交状态筛选，以及日交付数量和截止时间提示。
- 根据专项真实使用情况，再安排批量调度和其他已获确认的执行环境。

验收：一条样本从本地归档到远端回执可完整追溯；重试不重复提交；上传失败保留本地文件；没有正式模板配置时不能误投旧 GSB 表单。

## 第一版延后的事项

- 重建旧版自动补题、长期题型配额和复杂候选库调度。
- 跨 Windows、Unity、GPU、固件等环境新增整套执行器。
- 全站视觉重设计和修复全部历史 GSB 功能。
- 自动分析样本、自动评分和自动生成 Feedback。这些不属于本期专项方案。

领域标签不能代替执行环境能力验证。安全、音视频、图形或数据任务需要特定环境时，先提供真实环境与证据采集方式，不一律套用原来的 Web/Docker 模板。

## 实施前与接入前的确认事项

| 事项 | 临时实施口径 | 影响范围 |
| --- | --- | --- |
| 正文单轮与后文多轮、继续说明冲突 | 按正文只跑首轮，不自动续轮 | 原会话“继续”例外等待确认 |
| 产物快照必需与后文非强制旧句冲突 | 按字段表和执行流程保存最终快照 | 归档和预检 |
| 专项方向与禁题交叉 | 不因领域标签自动放行，由专家确认具体工程题 | 题库与人工选题 |
| 正式表格截图仍有 A 字段前缀，完整模板未知 | 先做本地标准字段与通用导出 | 正式提交适配可后置，不阻塞单轮归档 |
| 非代码变更任务的快照与录屏口径 | 不以零代码差异自动拒绝；人工确认其产物证据 | 技术讨论、部分泛 Agent 需求等 |
| “其他”子方向的正式枚举 | 保留正文允许跨方向兜底的语义，核对提交模板 | 字段映射 |

## 整体验收清单

1. 正常交付、模型代码报错、工程故障、中断和录屏失败分别有明确且可恢复的状态。
2. 单轮不产生隐藏的第二次 Prompt；独立重跑不复用原 SessionID 和 TurnID。
3. Prompt、附件、轨迹、快照与录屏全部绑定同一次执行。
4. 多提交历史、数据库迁移、并发开始、重启恢复和上传重试均有针对性测试。
5. 专家可以检查原始证据、保存人工 Feedback，并导出完整字段。
6. 新专项没有调用样本 AI 分析链路，也不会提交到旧 GSB 表单。
7. 至少跑通一条实际专项任务的完整闭环，由专家实际核对证据和反馈后再开放批量使用。
