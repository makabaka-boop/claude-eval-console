用户最新要求：“bug题面 不要 要求实际运行”。本次据此把自动 Bug 出题改为静态源码核验，覆盖自然缺陷发现、路线独立核对、预置设计、概念卡、完整题面及独立审核。后续 Claude A/B 执行、验收和录屏流程保持现状。

## 当前规则

- 出题阶段只读源码、需求、已有测试文本和 Git 信息；不要求启动项目、安装依赖、运行测试、执行复现或参考修复试跑。没有运行、缺依赖不再是拒绝理由。
- 必须有具体代码位置、触发输入或状态序列、控制流/数据流推导，以及错误和正确结果。独立审核重新核对源码，困难/地狱、范围和历史判重继续执行。
- 预置仍限已有业务源代码，不改测试、配置、依赖和交付文件；保留补丁适用性、文件范围、代码引用、干净快照和 SHA/tree 检查。取消出题阶段的原固定测试通过、原始/预置前后运行对照、参考修复运行门槛。完整题面未经过独立审核，不能只凭预置分析放行。
- 记录明确标注 `verification_mode=static`、`runtime_verified=false`。`reproduction` 是触发场景，`actual` 是源码推导的错误，不能伪造日志、退出码或“已复现”。题面不追加实际运行要求。历史材料保留原文，不把历史运行证据改写成静态证据。
- Bug 选源改为优先尚未尝试或更久未尝试的来源，解决冷却后失败计数清零导致旧来源反复优先的问题。资格、配额、有限冷却与方向指纹不变，Feature 排序不变。
